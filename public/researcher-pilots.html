Three useful types of evaluation

01 · REPRODUCE

Can an independent machine get the same result?

Record exact inputs, verifier and toolchain versions, expected outcomes, failures and environmental dependencies. A reported PASS without executed steps is not reproduction.

02 · FALSIFY

Can a changed input pass when it should fail?

Mutate an artifact digest, an unknown checker tag, a prohibited action, or a required dependency. Distinguish a correctly signed input from an independently supported claim.

03 · TRUST BOUNDARY

Which assumption connects records to reality?

Identify the obligations between formal trace properties, production binaries, I/O, audit logs, and deployed behavior. Missing FaithfulLog evidence must remain visible.

What qualifies as useful independent evidence?

  
Our evaluation acceptance standard

  

    
Reproducible
Pin the source SHA and environment, give the exact command, expected output, and actual logs with executed test steps.

    
Falsifiable
Use a negative control that should be rejected. A properly signed false claim or unknown checker must not become proof.

    
Scoped
Write the precise mathematical or computational conclusion. State how signatures, empirical models, compiler behavior, and deployed logs enter the argument.

    
Auditable
Separate reviewer observations and acceptance policy from the verifier result. Keep confidential project materials private unless an authorized sharing channel is agreed.
