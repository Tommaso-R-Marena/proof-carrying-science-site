What does a finished PCS result actually mean?

A PCS result has separate layers. The package can be valid while a scientific claim fails. A claim can be computationally supported while a reviewer still declines to accept it. This walkthrough uses the actual PCS v0.6 result and receipt fields to make those distinctions concrete.

Educational walkthrough: the scenario values below are illustrative examples of the real v0.6 schema. They are not presented as a new live verification run. For executed evidence, use Validation and the Trust Center.
The whole PCS result in one sentence

30-second read

Three questions tell you what PCS actually established.

1 · Formally established by PCS logicThe delivered decision is bound to the exact typed claim and verifier rules.

This is the logic/decision layer. It does not prove arbitrary scientific truth.

2 · Reproduced or freshly checkedPackage integrity, declared environment/workflow facts, and supported scientific checks are independently rechecked.

The verifier does not simply trust a recorded PASS.

3 · Still trusted / outside the proofRuntime, operating-system/container behavior, cryptographic implementations, and unsupported domain semantics remain part of the trust boundary.

PCS should name these boundaries rather than hide them behind a green badge.

Bottom line: read the typed claim first, then the fresh replay result, then the remaining trust boundary.

What “valid” contains

PCS v0.6 verifies a chain, not one green checkbox.

1

Canonical inputs

Certificate, manifest, and signature records must use the exact accepted canonical byte representation.

2

Certificate signature

The certificate must authenticate under the expected Ed25519 producer key.

3

Package binding

Member set, byte sizes, SHA-256 values, certificate binding, and package signature are checked.

4

Environment replay

Human-confirmed reproducibility-environment claims are regenerated from the delivered source bytes.

5

Workflow replay

Confirmed static dependency claims must be rediscovered from the packaged source.

6

Scientific replay

Every supported evidence item is rerun rather than trusting recorded PASS/FAIL values.

7

Normalized decisions

The delivered decision set must exactly equal the set derived from the fresh replay.
