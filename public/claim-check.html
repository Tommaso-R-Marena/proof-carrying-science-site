        How to run the check yourself
        1. Install Lean 4.28.0 (see lean-lang.org for instructions). No other software is needed.
        2. Run lean ClaimCheck-obligation.lean in a terminal.
        3. If Lean prints only a line that starts with 'pcs_claim_0' depends on axioms: and lists nothing beyond propext, Classical.choice and Quot.sound, the proof checker accepted the statement. Any error means it did not.

        The file contains the fixed checker, your data as one number, the claim and the expected outcome. The proof checker parses the bytes and recomputes the statistic itself. Nothing computed by this page is taken on trust.

        What the proof covers and what it does not

        The Lean statement is about a fixed, published checker: it parses the exact bytes of the CSV file, selects rows, computes the statistic with exact fractions and compares it with the printed value at the printed precision. Standard deviations and correlations are compared by squaring, which a separate proof shows is the same as the real-number comparison.

        A proof does not show that the file is the data the authors analysed, that the sentence means this statistic, or that the number supports any conclusion. A refutation shows a mismatch for this file under this reading. It does not show that the paper is wrong.

        Supported: counts, shares, sums, means, medians, minima, maxima, standard deviations, standard errors, sample variances, Pearson correlations and two-variable least-squares lines, over one comma-separated table of at most 64 KB. Not supported: test statistics, model estimates, quantiles, distinct counts, weighted or transformed values, tables inside the paper, and several data files at once.
