2. What does your finding establish?

A counterexample is a concrete example that contradicts a claim. Here, it shows that the rewrite changed the rule's meaning.

3. Carry the evidence. Let someone else recheck it.

Your evidence file contains the rule identifier and the exact fictional facts. Another checker can recompute the result from those facts. It does not have to trust a recorded “PASS”.

What ran: the existing finite logic checker in your browser. What did not run: the Lean kernel or the production PCS verifier. The Lean download is source that still needs compilation. This example makes no claim about a real AI's behavior.

What is in the download? How can a technical reviewer check it?

A witness is the small set of facts that demonstrates the difference. The JSON file uses the existing PCS Countermodel Lab format. It contains no signature or authoritative verdict.

With the PCS core CLI installed, independently recompute the finite result:

pcs countermodel-check-v1 pcs-first-witness.json

Or compile the generated proof source using Lean 4.28.0:

lean PCS_Countermodel_implication-flip.lean

Lean is a proof checker. Successful compilation checks this concrete mathematical statement; it does not prove that the rule describes a real system. The generated file imports only Lean's standard library.
