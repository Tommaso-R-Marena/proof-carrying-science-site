Filter the current PCS assurance stack by epistemic status. Each card states what the layer contributes and what remains outside that layer.

PROVED

Canonical v0.6/v2 representation

Machine-checked parsing, package structure, exact member/index commitments, and scoped decision semantics connect accepted canonical values to the formal assurance layer.

Lean kernel/runtime remain foundational TCB.
PROVED

SHA-256 = FIPS 180-4

sha256_eq_fips1804 proves the Lean SHA-256 implementation equal to an independent bit-level FIPS 180-4 specification on every input.

SHA-256 collision resistance is not claimed or required as a theorem of the algorithm.
PROVED

Canonical raw ZIP decoding

decodeZip_sound proves the Lean decoder's result satisfies canonical stored-ZIP semantics: matching headers, unique names, exact byte boundaries, and no trailing bytes.

Legacy/non-canonical ZIPs remain on the explicitly less-assured Python materialization path.
PROVED

All six built-in replay semantics

The compiled authority independently replays reaction_balance, unit_compatible, csv_disjoint, pkpd_contract, pkpd_reference_match, and pkpd_peak_concentration_threshold with proved Lean checkers.

Recorded PASS values are not trusted for these six.
PROVED

Real-valued PK/PD meaning

pcs_pkpd_reference_match_real connects an accepted PK/PD reference-match PASS to the declared real analytic model with a certified exponential enclosure and committed tolerance.

This proves agreement with the declared model, not empirical adequacy of that model.
PROVED

Frontier archive acceptance

pcs_frontier_archive_acceptance_sound starts from accepted raw canonical archive bytes and concludes exact archive partition plus HighAssurance.

Its only theorem hypothesis is NoForgery for the Lean Ed25519 trust anchor.
CHECKED

Workflow front-end regeneration

Python re-extracts normalized literal-reference workflow facts from committed source bytes; Lean checks the normalized FreshSource records and proves WorkflowDescribes relative to them.

The source analyzer itself is not yet proved in Lean.
CHECKED

Environment capture with verified subset

The authority checks verified EnvFacts covering exact == pins, SHA-256 pins, .python-version, and digest-pinned container bases.

Meaning beyond this subset—such as broader lockfile/reconstruction semantics—remains explicit.
CONTRACT

Ed25519 hardness + RFC 8032 correspondence

NoForgery remains the frontier theorem's sole cryptographic hypothesis. The Lean Ed25519 verifier is vector-tested, but equivalence to an independent RFC 8032 group-law specification and SHA-512/FIPS correspondence remain open.

PCS also proves that unauthorized acceptance yields a valid forgery for the trust-anchor key.
CONTRACT

External validators and legacy ZIPs

Evidence kinds outside the six certified built-ins need their own semantic adapter; non-canonical ZIPs use the legacy Python path and do not inherit canonical raw-byte ZIP soundness.

Both boundaries are fail-closed and explicitly labelled.
CONTRACT

Operational invocation boundary

Lean 4.28, the compiled authority runtime/toolchain, and the Python driver that prepares observation transcripts remain operational components around the theorem.

Python-only acceptance cannot produce authoritative valid:true.
NOT CLAIMED

Biological or clinical truth

A valid PCS package supports its exact typed computational claim. It does not automatically establish biological efficacy, clinical validity, or causal truth.

NOT CLAIMED

Regulatory approval / GxP validation

PCS assurance is not itself regulatory authorization, quality-system certification, or a substitute for domain governance.

NOT CLAIMED

Correctness of arbitrary code

PCS is deliberately fail-closed and scoped to supported predicates/checkers. Unsupported software does not become proved merely by entering a package.
