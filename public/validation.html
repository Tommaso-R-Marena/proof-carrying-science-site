Strongest negative result

Real measured PK data did not get a free PASS.

The public Indometh dataset contains intravenous indomethacin plasma concentrations over time. Subject 1 was fit with the best log-linear single-exponential curve and those measured concentrations were then intentionally presented to the PCS replay predicate as though they were exact deterministic model output.

Canonical demo suite

Three deterministic examples tell the whole PCS story.

These are not screenshots or hand-written result cards. The core harness constructs, signs, bundles, and independently verifies each v0.6 case. A fixed demo-only signing key and fixed fixture timestamp make repeated builds byte-comparable.

01 · Supported

Valid package + supported claim

A restricted PK/PD model and its declared output replay exactly within the typed tolerance. The bundle must be valid and both computational claims must derive COMPUTATIONALLY_SUPPORTED.

02 · Falsified

Valid package + failed scientific claim

The output is deliberately corrupted while the package remains structurally valid. PCS must preserve FALSIFIED_OR_CHECK_FAILED rather than confusing scientific failure with verifier failure.

03 · Reproducibility

Environment-bound replay

Discovery captures declared Python dependencies and interpreter constraints, confirmation binds their exact source bytes, and verification re-derives the environment proposition before scientific replay.

python scripts/run_golden_examples_v06.py -o golden-demo-run
Demo-only cryptographic identity: the golden suite intentionally uses a deterministic test key so byte-for-byte reproducibility can be asserted. That key is never appropriate for real publication or reviewer trust.

Adaptive validation / RL

RL may schedule checks. It may not decide scientific truth.

We evaluated adding reinforcement learning to the architecture. It does not improve the correctness of deterministic replay and would unnecessarily enlarge the verdict trust boundary. A future bandit/RL scheduler could learn which expensive mandatory checks are most likely to fail and run those earlier, reducing time-to-failure. Acceptance would still require every mandatory check, and the scheduler's output would remain untrusted.

Allowed

Order checks

Use historical benchmark cost/failure data to prioritize the next expensive check.

Not allowed

Skip evidence

No policy-required or claim-required check may be omitted because a learned policy thinks it is unlikely to matter.

Not allowed

Change verdicts

PASS/FAIL and reviewer acceptance remain deterministic functions of verified evidence and explicit policy.

Current limit: these results establish behavior on five targeted real-world cases. They do not establish broad pharmacometric validity, general chemistry coverage, general ML leakage detection, or end-to-end v0.6 formal verification.
