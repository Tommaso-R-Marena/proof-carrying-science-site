# What these results establish

The current evidence establishes that the implemented synthetic fixtures, scenario extraction and deterministic in-memory authorization guards produce their expected outcomes on the tested cases. It does not establish that a real AI system is safe.

- **No real model evaluations were run.** The optional provider path was tested through mocked HTTP transport. Mock tests carry the `fixture/simulated` label, even when they exercise the official SDK. They do not count as live calls.
- **No human playtest study was run.** The source comparison uses a scripted `synthetic-player` stand-in, a seeded random generator and a small automated baseline. Differences are determined by how those generators were written.
- **Three fixed families and nine public wordings are narrow coverage.** There is no held-out benchmark, demonstrated transfer, attacker-optimal search, established novelty, comparison to professional red-teamers or resistance to arbitrary prompt injection.
- **The vulnerable fixture is intentionally wrong.** It uses the condition label to select a bad action. Its attack rate is an expected test outcome, not an observed language-model vulnerability. The live adapter omits condition and answer labels from the model prompt.
- **The real-model adapter evaluates one-turn plans.** There is no tool-result feedback loop, autonomous browser, long-horizon agent, model-weight integration or measurement of real-world side effects. A compatible operator-specified model and account are required before this path can be evaluated live.
- **The guards are ordinary TypeScript code.** They have schema checks, exact allowlists, independent deterministic tests and adversarial fuzzing. They have no Lean proof, hardware isolation or immutable trusted root. A compromised runtime, altered source or privileged local operator can change them.
- **Hashes provide integrity checks, not authenticity.** A local operator can edit a capture or replay and recompute its hashes/checksums. A valid hash does not prove a person played, a model was queried, the host was trustworthy or an outcome happened externally.
- **Local scores are editable.** There is no global leaderboard, anti-cheat authority or authoritative public ranking.
- **The game is a synthetic laboratory.** Courier routes, guard behavior and technician repairs are finite-state gameplay. Their failures do not measure LLM alignment, deceptive intent, corrigibility, autonomous capability or recursive improvement.
- **Confidence intervals have limited meaning here.** Fixture outcomes are deliberately programmed. Future model trials require independent samples, explicit error denominators, repeated seeds, frozen settings and a justified analysis of correlated/adaptively selected attacks. A pooled rate across good and vulnerable fixtures is not a model score.
- **Provider compatibility and cost are unmeasured.** SDK types and mocked requests were checked, but an actual model may reject a setting or tool schema. Such results must be reported as provider errors. Completion-token and call caps are not a guaranteed dollar budget; input-token charges and provider policies still apply.
- **Nothing is donated by default.** Local capture is optional. JSON export is an explicit local download, not permission to publish, train on or upload a record. An operator can deliberately pass a validated exported synthetic scenario to the CLI; the privacy consequences of any separate sharing remain that operator's responsibility.

A useful next validation would be an explicitly authorized, paired live evaluation against a pinned model, followed by a small consented human playtest. Freeze the scenarios before evaluation, publish negative results alongside positive ones and test transfer on genuinely unseen wording. The current implementation makes those experiments reproducible; it has not performed them.
