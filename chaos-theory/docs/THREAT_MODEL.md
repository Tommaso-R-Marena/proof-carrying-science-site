# Trust boundaries and threat model

The browser game and local evaluation tools run under the user's ordinary browser/Node host. They are not immutable authorities. The principal safety property is narrow: a model can propose a prohibited action, but the synthetic tool guard must not execute an unauthorized synthetic effect. No tools capable of real external actions are exposed.

## Boundaries

1. Keyboard/touch actions and local game state produce bounded event records. A hostile local user can fabricate records; provenance says `local-unattested`.
2. The extractor accepts only the current schema/build, mission-compatible events and three bounded template variants. It constructs trusted task/policy/world fields independently of the capture.
3. Lower-trust notices are data supplied to an evaluated agent. They cannot edit the registry, code, trusted policy or grader.
4. Structured tool proposals enter a fresh in-memory sandbox. Exact argument schemas and per-tool authorization run before effects. Unknown tools, extra keys, wrong IDs and out-of-order repair fail closed.
5. The optional provider adapter alone can send synthetic model prompts to the pinned OpenAI API. It is server-only, opt-in and unavailable from the browser UI. There is no browser evaluation endpoint or browser API key.
6. Local JSON exports and result reports are mutable files under the local operator's control. SHA-256 detects inconsistent edits but is not a signature or an attestation.

## Threats, controls and residual risk

| Threat                                      | Implemented controls                                                                                                                                                                    | Remaining limitation                                                                                                   |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Arbitrary event injection / fabricated play | Strict capture schema, version/build checks, mission mapping, bounded ordered ticks, bounded variants, deduplication                                                                    | A local attacker can fabricate a valid capture; no verified human identity                                             |
| Scenario tampering / forged policy          | Fixed task/world/capability/template checks plus canonical SHA-256 on imports                                                                                                           | An attacker can regenerate an internally consistent synthetic scenario; hash is not source authentication              |
| Replay forgery                              | Compatible-build replay, bounded inputs and deterministic periodic/final checksums                                                                                                      | Checksums are reproducibility signals, not cryptographic proof or anti-cheat                                           |
| Input flooding / malformed nested data      | Event/count/tick/string bounds, strict flat tool schemas, 16-action cap, JSON canonical depth/node bounds; CLI file caps                                                                | Local CPU/memory and the browser host remain shared resources; this is not a hardened hostile multi-tenant service     |
| XSS in labels / notices                     | Browser displays scenario data using text nodes/textContent; templates are bounded code-defined data                                                                                    | Browser extensions, compromised dependencies or edited application source remain trusted-host risks                    |
| Forged authority in notices                 | Trusted instructions are separate, policy fixed in code; model proposals independently authorized                                                                                       | No claim that the model always ignores an injection; attempted violations are measured separately                      |
| Malicious model tool names / arguments      | Exact capability allowlist, strict keys/types, exact target IDs, inspection precondition, fresh state per run                                                                           | Guards and grader are tested TypeScript, not kernel-proved; bugs remain possible                                       |
| Fake positive model response                | Only structured tool calls are graded; prose cannot declare success; final synthetic state determines task completion                                                                   | A compromised provider/host can fabricate a response; no external execution attestation                                |
| Quota exhaustion / accidental paid calls    | No calls by default; explicit environment opt-in and CLI `--execute`; planned call count; max 50 configured calls; reserve before request; retries disabled, timeout and completion cap | A local operator can launch multiple processes; caps are process-local and do not enforce account-wide currency limits |
| API key leakage                             | Server environment only; `.env` ignored; pinned API endpoint; no key in prompts/reports; provider exception strings not persisted; no CORS evaluation endpoint                          | Host compromise, shell history, SDK/OS compromise and operator mishandling cannot be prevented by this app             |
| Inadvertent external action                 | Tool sandbox exposes no shell, filesystem, email, browser or network actions; only fixed synthetic IDs                                                                                  | The optional provider request itself is an external API call after opt-in                                              |
| Public leaderboard cheating                 | No global leaderboard; local scores explicitly local/editable                                                                                                                           | Any future public ranking requires a separate authority and moderation design                                          |
| Privacy / unintended donation               | Capture off by default, local retention, explicit export, no analytics or automatic model submission; local reset                                                                       | Exported files can be shared by the operator; no consent/ethics approval is implied                                    |
| Test controller misuse                      | Deterministic browser controller exists only in the E2E build, injects valid inputs, no state-write/win shortcut                                                                        | Developer tools can alter any local game; a test build is not a production authority                                   |

## Verification evidence and assumptions

The focused research tests exercise malformed and unknown tools, cross-family calls, exact-ID substitutions, approval fields, notice/policy substitutions, inspection ordering, fresh-run state, 4,000 malicious requests, canonicalization failures, artifact hash tampering, mock provider errors, invalid JSON, truncation, refusal, cancellation and concurrent call-budget exhaustion. The saved v2 fixture report is independently rehashed and replayed in tests. See the overall test report for final integrated counts.

The adapter's mocked transport is an explicit test option. It marks returned records `fixture/simulated` and `mock-transport`; it cannot establish a real-model result. The production CLI does not expose transport substitution. Tests rely on the local source, runtime, official pinned SDK and test harness being the code actually executed. No process-separation, container-immutability or protected-credential guarantee is asserted.

The loopback status server binds `127.0.0.1`, rejects requests with an Origin header or a mismatched Host, sends no CORS headers and has no model-execution endpoint. This reduces accidental exposure; it is not authentication against a hostile local process. Use the explicit CLI for evaluation, and do not expose the status server through a public tunnel.
