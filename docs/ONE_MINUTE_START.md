# A simpler first visit

PCS's first screen now explains the product in ordinary language:

> PCS checks specific rules in data and calculations. It shows what passed,
> what needs attention, and how someone else can check the same result.

The first task is a familiar question: do two lists share an ID? Three rows in
each fictional list are visible without choosing a file, configuring columns,
learning logic, opening an account or downloading an app. The checker finds ID
103 on line 4 of Group A and line 2 of Group B. A second pair of lists contains
no shared IDs. Results depend on the actual parsed bytes.

## Implementation and boundaries

`one-minute-core.mjs` imports the existing `file-check-core.mjs` parser, ID
analysis, hashes, report renderer and canonical replay format. It changes no
verification authority or mathematical specification. `one-minute.mjs` supplies
presentation, focus management, explicit check actions and local downloads.

The readable HTML report records a browser calculation and states its scope.
The JSON recheck file includes both fictional source CSVs and their hashes; the
existing file tool can reopen it and independently recalculate the summary.
It contains no affirmative Lean receipt. Matching IDs do not establish that
names, people or other details are correct. No model inference or kernel proof
is claimed for this browser example.

Changing the example clears its result, highlights and export authorization.
Asynchronous hashing disables conflicting controls until the snapshot is ready.
A missing JavaScript module leaves the initial buttons disabled and establishes
no result. Original private files are never requested by this introduction.

The landing page offers an example, the own-file tool and optional research.
The two entry pages use three navigation links; other tools retain their existing
menus and account access. The prior rule investigation and all its proof-source
and evidence downloads remain in a collapsed optional section. Existing bookmarked
sections open their enclosing disclosures. A link targeting a disclosure itself
also opens it, fixing the previous fragment-navigation omission.

## Validation

The protected website gate includes the one-minute unit tests in its existing
experience suite and the expanded four-width beginner browser journey. The
supplemental first-investigation workflow runs the same updated path. Checks cover:

- Actual shared-ID and disjoint outcomes and their exact source lines.
- Both canonical replay exports reopened in fresh instances of the file tool.
- Readable HTML report contents and explicit absence of a Lean verdict.
- Changed-input invalidation, disabled exports, keyboard activation and focused results.
- Three-link entry navigation, optional legacy investigations, research bookmarks,
  game completion and source-bound package inspection.
- Desktop and phone layout, no external requests or upload writes, missing-module
  failure and no-JavaScript fallback.

The unchanged legacy logic checker retains its exhaustive truth-table, hostile
import, delayed-read and generated Lean-source checks. Research and file-checker
source-integrity gates remain required.

**The one-minute goal is a design target, not a measured human result.** Automated
browser completion is evidence that the controls work. A separate newcomer study
is needed to measure comprehension and discover where people still get stuck.
No participants, adoption rates or human completion times are invented.

Local validation evidence is in `docs/evidence/one-minute-start-v1/`. The
Chromium run covers 320, 390, 768 and 1440 pixel widths: 12 existing learning,
game and inspection journeys plus both introductory replay variants reopened
in a fresh file-checker page at each width. It records zero external requests
and zero writes. Initial introduction text is 159 words on phones and 184 at
the larger widths. The expanded legacy investigation passes all four widths,
including four rejected hostile file forms and delayed-read invalidation.
The complete Node suite passed 540 tests with none skipped; the complete local
Cloudflare build gate and dry-run deployment passed. These are local results;
protected GitHub CI is the separate integration requirement.
