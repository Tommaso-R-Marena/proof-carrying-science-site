# Guided proof workbench v1

The workbench connects a beginner-facing flow to the existing protected-source
public proof service. It has 87 controlled forms: six logic/list examples and
81 bounded number-offset questions. Its preview catalog is regenerated from the
exact pinned PCS translator and checked in CI. The preview itself runs no Lean.
Unrecognized text stays local and is rejected before any publication.

Users review the actual mathematical statement, explicitly confirm its intended
meaning, then separately consent to public CC0 mathematical input. Private
context and optional study answers are neither sent nor exported in proof
reports. The fast portfolio tries ordinary Lean tactics, structural memory and
the frozen neural policy; the learned-memory option includes explicit comparison
methods and bounded counterexamples. Results identify the actual successful
role/component. Unknown is distinct from refutation.

A saved acknowledged ticket resumes by reading that ticket, without submitting a
new workflow. An interrupted submission without acknowledgment retains its
idempotency key; retry it from the same client/network. Provider-side uncertainty
never becomes proof. Cancellation remains unconfirmed until the provider says so.
Older translator requests and broader exact-human-action paths can be recovered
in the advanced lab. Tab metadata never establishes mathematical correctness.

The portable JSON contains a source-bound evidence projection: complete proof
receipts/typed actions, statements, source/checkpoint identities, comparison
outcomes and budgets. Redundant search-state/attempt traces are omitted; a digest
of the full provider evidence and the original public job link are retained.
The original evidence is not overwritten. Its checksum is not an authority
signature. The readable HTML embeds the matching JSON and reviewed Lean source,
works offline and can download both. Its only executable code is a fixed,
CSP-hashed download helper; embedded report data is escaped and never executed.

## Independent receiver replay

Use Python 3.12, the PCS build/dev locked dependencies, and the official
hash-pinned Lean 4.28 toolchain. Check out the exact *trusted* core commit shown
in the report. No neural weights or model API is needed to verify a proof.
Keep source bytes unchanged (including LF line endings). The receiver has a
locally shipped source-hash trust profile; an imported report cannot select an
arbitrary Python verifier or library. Source-identical later commits may match
that profile, while actual package/adapter/library changes require an explicitly
reviewed profile update. A trusted host, bytecode cache and toolchain remain
assumptions. From the website repository:

```sh
python scripts/replay_proof_workbench.py --core /path/to/trusted/core report.json
```

The receiver checks the raw canonical-payload byte digest, JSON semantic equality,
closed report scope, exact local source, controlled-language interpretation,
original goal, comparison attribution and actual kernel type/axioms. It
regenerates commands from bounded typed actions with the trusted local library,
receiver-owned Std tactics or the typed finite witness whitelist. It never
executes arbitrary Lean source supplied by a report. Unknown reports establish
neither truth nor falsity. A successful replay establishes the encoded theorem
under the printed Lean assumptions; it does not attest physical neural
computation, user intent, scientific truth or a trusted OS/toolchain root.

A semantic catalog identity excludes the current operational core-revision
pointer. Source-identical pin updates preserve archived examples and report
meaning. Fresh requests still require exact agreement between the preview and
live approved source. Actual semantic changes require review and a new catalog
identity; frozen reports are never silently rewritten.

## Evaluation and maintenance

The prospective evaluation protocol and cases were committed before evaluation
in `research/proof-search-prospective-v1/`. The same frozen memory policy and
strong symbolic baselines get the same external wall/call caps. This is an
authored post-checkpoint study, not an independently blind benchmark. Results
include setup, search and separate independent replay costs and retain failures.

`scripts/propose_core_sync.py` detects current protected-core drift as Git data.
It does not execute candidate code with a write credential. Only documentation-only changes outside frozen report paths qualify for an
automatic pin proposal. If any executable, unknown, model, Python,
formal, dependency, public-workflow or frozen-document path changes, it proposes
a blocked draft report without changing execution pins. Source-identical changes
can produce a draft pin-update PR preserving model bytes and historical evidence.
No proposal automatically merges or promotes a model. Compatibility workflows
are dispatched explicitly so bot-generated proposals receive actual checks.
GitHub must allow the repository token to create PRs; a permission rejection is
an operator setup issue, not evidence that a PR or qualification exists.

## Qualified evidence and limitations

The frozen study's two physical runs reproduced 8 learned / 8 structural /
11 strong-baseline proofs per 14 cases, using 248 / 224 / 50 charged search
Lean attempts. Both runs have been independently received again (54 positive
proofs total); three separate false-control counterexamples replay with no
axioms. There is no learned unique-solve gain. Read the full protocol, raw records,
setup-counter disclosure and source provenance in
[the prospective study](../research/proof-search-prospective-v1/README.md).

Local verification includes 533 complete Node tests with zero failures or skips,
nine new Python tool tests, all 87 preview types actually elaborated by Lean,
strict source checks and actual report replay. The receiving adversarial campaign
rejects producer Lean commands, producer library substitution and a
producer-selected fake Python core without executing their marker writes.
Browser checks at 320/390/768/1440 pixels use explicitly labeled recorded-provider
fixtures; they establish UI behavior, not fresh authorization or human usability.
The managed local browser blocks the file URL scheme, so those checks render the
exact downloaded HTML bytes via loopback, then disable network for download.
The machine record retains `file_scheme_tested: false`; CI tests the file scheme
where its browser policy allows it. No policy bypass is used.

Protected CI requires frozen independent study replay as a separate job and
includes its result in the final site gate. Current-source browser CI regenerates
the entire preview and elaborates every statement as a Lean type (this does not
prove false statements). Full fresh CPU neural study reproduction is a separate
manual workflow. It is not a skipped core verification job. Frozen evidence stays
pinned to its historical core even when reviewed current-service pointers advance.

[The optional pilot](PROOF_WORKBENCH_PILOT_V1.md) is operational tooling and a
predeclared small-pilot protocol, with zero recruited participants. Human task
completion and comprehension remain unresolved empirical questions. Physical
neural execution, host integrity, compilation and intended user meaning remain
outside the theorem guarantee. No new scientific acceptance authority, production
self-modification, general English proving, model promotion or new Lean library
axiom has been introduced.

Original protocol/evaluator Git objects are retained in a hash-bound data-only
bundle, because the host enforces linear-history merges. Receiving CI imports
those objects, verifies the original commit/source hashes and protocol ancestry,
and never checks out or executes archived producer code. Self-contained bare-Git unit fixtures test data-only restoration and missing-parent
rejection without depending on checkout depth. A required full-history receiving
integration test additionally reconstructs the actual original evaluator in a
fresh bare repository with those old objects absent. Historical result files remain byte-identical.

Live mobile inspection found the exact-statement preview had inherited pale text
from the global dark code-block theme. Its measured contrast was 1.12:1. The
scoped light-panel foreground now measures 16.74:1 at all four tested widths;
the browser gate requires at least 4.5:1 for this normal-sized text. Editing a
claim or rejecting an imported report clears the previous visual result, identity,
job link and downloads. An unresolved offline report disables its Lean-source
download. These are automated accessibility and state checks, not human study
results. Original evidence files are retained alongside the new readability run.

The deployed workbench submitted actual public job 41372284199 through the
frozen learned memory policy. Its report and qualification are archived in
`docs/evidence/proof-workbench-v1/live-model-*`. Independent typed-action replay
and standalone Lean compilation succeeded with no axioms. Source assets matched
website revision `0f01989e9cf6275e55c24110ab1a921d02f4549c`; private context was
excluded. This is an execution qualification on a supported example, not a new
held-out sample, model advantage or independently attested neural computation.
